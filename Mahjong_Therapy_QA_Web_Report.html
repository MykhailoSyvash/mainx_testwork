01 / Executive summary

Резюме ризиків

Базове проходження стабільне, але є сильні ризики у solvability, monetization, Daily Goals та modal state handling.

Ключові ризики

Level 17 у pair-механіці може перейти в нерозв’язний state без recovery path.
Rewarded ads не показуються, але reward видається одразу.
Booster через “+” безкоштовно обходить acquisition/monetization flow.
Daily Goals можна повторно фармити через відсутність trusted time validation.
У pair A/B-групі є hand-специфічна Daily Goal, яку неможливо виконати.

04 / Product thinking

UX та продуктові рекомендації

Окремо від дефектів: покращення зрозумілості, консистентності та player experience.
REC-01

Зробити описи Daily Goals самодостатніми

Назви на кшталт “Hit full combo” не пояснюють, яку конкретно дію очікує гра. Додати короткий description, tooltip або приклад умови виконання.

REC-02

Пояснити, що таке IQ і на що він впливає

IQ показується поруч зі Score та Combo як ключова метрика, але не пояснюється її формула, накопичення або вплив на progression/rewards/ranking.

REC-03

Показувати Daily Goal completion одразу в момент виконання

Tracking відбувається під час gameplay, але completion tip може з’явитися лише після завершення рівня. Миттєвий feedback зробить прогрес зрозумілішим.

REC-04

Додати preview milestone reward у Daily Goals

Gift icon варто зробити tappable та показувати tooltip/preview, щоб гравець розумів, за що працює.

REC-05

Розглянути “Highlight free tiles” як default-on

Для casual-аудиторії затемнення blocked tiles зменшує cognitive load і швидше пояснює доступні ходи.

REC-06

Уніфікувати Settings icon

REC-12

Окремо перевірити analytics identity persistence при interrupted first launch

Analytics SDKs ініціалізуються дуже рано. Варто звернути увагу, чи на момент відправки перших івентів в аналітику у юзера створився сейв чи ні, аби не було ситуації, коли юзер закриє гру після відправки перших івентів, але перед створенням сейва, і потім заходить повторно. Іноді буває що при повторному заході нові івенти летять з новим юзер айді. І в аналітиці буде якийсь % юзерів, які зайшли в гру але не дійшли до тутора, і не буде зрозуміло чому, а по факту це просто дублі.

06 / Technical notes

Технічні спостереження

•Remote Config через rc.print: ab_active_module=hand, ads_ab_group=_default, inter_cooldown=60, inter_delay_hours=0, inter_min_level=4, inter_session_delay_seconds=60, rewarded_min_level=1.
•Збірка Unity IL2CPP; у трафіку/ініціалізації спостерігалися Firebase, AppsFlyer, Meta, devtodev та Google-сервіси.
•HTTPS payload-и не аналізувались на рівні body через production/non-debuggable build та обмеження certificate interception. Це coverage limitation, а не дефект.
•Внутрішній app sandbox недоступний через run-as, оскільки package non-debuggable; обходи/рут не використовувались.
•Debug A/B switch під час активного tutorial може тимчасово ламати pair tutorial interaction, але після виходу/повторного входу state відновлюється; production finding не створювався.
